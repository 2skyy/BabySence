## 1. 실기기에서 확인해 주실 것

제가 할 수 없는 것들입니다. 시뮬레이터로는 알림·마이크·카메라를 믿을 수
없습니다.

### 시작 전 준비 — 상담(챗봇)을 보시려면 필요합니다

앱은 기본적으로 `10.0.2.2:8000`(안드로이드 에뮬레이터) 또는
`127.0.0.1:8000`을 봅니다. **실기기에서는 둘 다 닿지 않습니다.**

```bash
# 1. 서버를 켭니다 (PC에서)
cd server && ./venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 2. PC의 내부 IP를 확인합니다
ipconfig getifaddr en0

# 3. 그 주소를 앱에 넘깁니다
flutter run --dart-define-from-file=env.json \
            --dart-define=API_BASE_URL=http://<PC의 IP>:8000
```

기기와 PC가 같은 와이파이에 있어야 합니다. 준비가 번거로우면 상담만 빼고
나머지를 먼저 보셔도 됩니다.

## 2. 알려진 문제

고칠 수 있는 것부터 순서대로.

### A. 체온을 저장하다 실패하면 기록이 중복될 수 있습니다 **[확인함]**

`TemperatureRecordService.save()`가 두 번에 나눠 넣습니다.

```
1) temperature_records  insert ... select().single()
2) temperature_symptoms insert (증상이 있을 때만)
```

2단계가 실패하면 **1단계는 이미 저장돼 있는데** 화면은 "저장하지 못했습니다"를
띄웁니다. 다시 누르면 같은 체온이 한 번 더 들어갑니다.

증상을 고른 사용자만 겪습니다. 고치는 방법 두 가지:

- **간단** — 2단계 실패를 치명적으로 보지 않습니다(판정 저장이 이미 이렇게
  돼 있습니다). "체온은 저장됐고 증상은 저장하지 못했습니다"로 알립니다.
- **정확** — Postgres 함수 하나로 묶어 한 트랜잭션에 넣습니다. 마이그레이션이
  하나 더 필요합니다.

### B. 조회 실패를 "기록 없음"으로 보여줍니다 **[확인함]**

홈 화면이 오늘 기록을 못 읽으면 `debugPrint`만 하고 넘어갑니다. 타일에는
`기록 없음`이 뜨는데, 이건 **기록이 정말 없을 때와 글자가 같습니다.**

```dart
// home_page.dart
catch (e) { debugPrint('오늘 기록 조회 실패: $e'); }   // 화면에는 아무 표시가 없음
String _tileSubtitle(String? value) => value ?? '기록 없음';
```

마이페이지도 같습니다. 예방접종 화면은 오늘 고쳤습니다(빨간 안내).

같은 방식으로 홈·마이페이지도 "불러오지 못했습니다"를 따로 보여주면 됩니다.

### C. 소음 판정이 근거 없는 숫자를 씁니다 **[확인함]**

`noise_rules.dart`에 WHO 1999 기준을 만들어 뒀는데, 정작
`noise_result_page.dart`는 아직 출처 없는 50/70dB를 씁니다.

**바꾸기 전에 D가 먼저입니다.** 보정이 틀리면 기준을 옳게 바꿔도 값이
틀립니다.

### D. 마이크 −15dB 보정이 검증되지 않았습니다 **[미확인]**

`main.dart`의 `_micOffsetDb = 15.0`은 경험적으로 정한 값입니다. 실제
소음계와 대조한 적이 없어, 앱이 "30dB"이라고 할 때 정말 30dB인지 알 수
없습니다. 소음 기능 전체가 여기에 걸려 있습니다.

휴대폰 소음계 앱만으로는 부족합니다(그것도 보정되지 않았습니다). 학교
실습실에 소음계가 있으면 그것과 맞춰 보시는 게 가장 빠릅니다.

### E. 피부 분석에 모델이 없습니다 **[확인함]**

서버가 503을 반환합니다. 이전 파이썬 서버는 항상
`Atopic Dermatitis 88.4%`를 돌려줬는데, 고정값을 진단처럼 보여주는 것은
사용자를 오도하므로 가져오지 않았습니다.

골격(응답 형식·컷오프·업로드 상한)은 준비돼 있어, 모델이 생기면
`server/app/skin.py`의 `load`/`predict`만 채우면 됩니다. 학습 데이터는
`~/baby_skin_data`에 있고 클래스는 9종입니다.

### F. FCM이 동작하지 않습니다 **[확인함]**

`google-services.json`과 `GoogleService-Info.plist`가 둘 다 없어 Firebase
초기화가 실패합니다(앱은 계속 뜹니다). `device_tokens` 표와 예방접종 알림이
여기 걸려 있습니다.

수유 알림은 여기에 **걸리지 않습니다** — 기기 안에서 도는 로컬 알림이라
Firebase가 없어도 됩니다.

### G. 소셜 로그인이 서버에서 꺼져 있습니다 **[확인함]**

코드는 준비됐지만 `/auth/v1/settings`에서 Google·Kakao 둘 다 `false`입니다.
Supabase 대시보드에서 켜고 Redirect URL(`babysense://login-callback`)을
등록해야 합니다. 절차는 [social-login-setup.md](social-login-setup.md).

애플 로그인은 미구현이고 Apple Developer Program 가입이 필요합니다.
iOS 앱스토어는 소셜 로그인이 있으면 Sign in with Apple을 요구합니다.

## 3. 배포 전에 반드시

지금은 **개발 PC에서만** 돌아갑니다. 밖에 내보내려면:

- [ ] **서버 배포** — `/api/advice`가 있어야 상담이 됩니다. 인증(Supabase 토큰)과
      횟수 상한은 이미 들어가 있습니다.
- [ ] **CORS** — 기본값이 "아무 출처도 허용 안 함"입니다. 웹에서 부를 일이
      생기면 `CORS_ORIGINS`에 그 주소만 넣으세요. 모바일 앱은 영향 없습니다.
- [ ] **`ANTHROPIC_API_KEY`를 배포 환경 변수로** — 저장소에 넣지 마세요.
      `server/.env`는 gitignore돼 있습니다.
- [ ] **횟수 상한 재검토** — 지금 사용자당 30회/시간, 전체 300회/시간입니다.
      한 프로세스 안에서만 세므로 워커를 여러 개 띄우면 실제 상한은 그
      배수가 됩니다.
- [ ] **`ADVICE_MAX_TOKENS`** — 지금 4096. 답변이 자주 끊기면 올리세요
      (`truncated: true`가 오면 끊긴 것입니다).

## 5. 정리해야 할 것

### 운영 Supabase에 남은 테스트 계정

아이와 기록은 지웠지만 **계정 자체는 남아 있습니다.** `auth.users` 삭제는
`service_role` 키가 필요한데, 그 키는 RLS를 우회하므로 쓰지 않았습니다.
Supabase 대시보드 → Authentication에서 지우세요.

```
community-check@babysense.dev, community-other@babysense.dev
migration-005-check-*, tz-check-*, tz-fixed-*, upsert-*, upsert2-*
advice-auth-check-*        (2026-08-12, /api/advice 인증 확인)
mig-check-a-*, mig-check-b-* (2026-08-12, 006·007 왕복 확인)
```

아이 `검증아기`(`edde3912-…`)와 딸린 기록 4건도 남아 있습니다.

### 로컬 PostgreSQL

`brew uninstall postgresql@16`. 004 검증과 006·007 사전 확인에 썼습니다.
앞으로도 마이그레이션을 운영에 넣기 전에 돌려 볼 곳이 필요하니, **논문이
끝난 뒤에** 지우시는 편이 낫습니다.

### 문서

- **ERD 명세가 미완입니다** — 표는 20개인데 `docs/erd.md`의 명세서는 12개만
  다룹니다. 커뮤니티(`posts`/`comments`), 함께 키우기(`baby_members`/
  `baby_invites`), 약·병원(`medication_records`/`hospital_visits`)이 빠져
  있습니다. 논문에 ERD를 넣으신다면 채워야 합니다.

## 6. 논문 원고 수정

원고(`.docx`)는 저장소에 없어 제가 고칠 수 없습니다. 코드와 어긋나는 곳만
적습니다.

| 절 | 원고 서술 | 실제 |
|---|---|---|
| 시스템 구성 | 판정 규칙을 FastAPI가 수행 | **앱(Dart)의 규칙 엔진**이 계산합니다. 서버는 추론과 상담만 |
| 시스템 구성 | 서버가 범위 검증 | 범위 검증은 앱과 DB의 CHECK 제약이 합니다 |
| DB | 테이블 14개 | **20개** |
| 초록 | "체온·성장·수면·수유" 판정 | 판정이 있는 것은 **체온·성장·소음** |
| 3-2절 ② ④ | "판단한다" | 수유·배변은 **기록하고 집계만** 합니다 |
| 3-2절 ⑦ | 접종 "가능 여부를 판단" | **확인 정보를 제시**합니다. 판정하지 않습니다 |
| 3-3절 | "6개월 초과" | 코드는 **6개월 이상**(`symptomNoteFromMonths = 6`) |
| — | 종합 판정 | 없습니다. 영역별 판정만 있습니다 |

**한 가지는 반대로 맞게 됐습니다.** "FastAPI가 Supabase Auth 토큰을 검증한다"는
서술은 예전엔 사실과 달랐지만, 2026-08-12에 `/api/advice`에 인증을 넣어
**이제 실제로 검증합니다.** 고치지 않으셔도 됩니다.
