## 0. 지금 붙여야 하는 마이그레이션

**010과 011을 아직 운영 DB에 넣지 않았습니다.** 앱 코드는 이미 새 모양을
전제하므로, 붙이기 전에는 소음 측정과 피부 저장이 어긋납니다.

Supabase 대시보드 → SQL Editor에 아래 두 파일을 **차례로** 붙여넣으세요.

1. `supabase/migrations/010_skin_analyses_no_diagnosis.sql`
2. `supabase/migrations/011_noise_stats_on_sleep_records.sql`

둘 다 **다시 돌려도 됩니다.** 로컬 PostgreSQL에서 두 번 적용해 확인했고,
마이그레이션 경로와 `schema.sql` 단독 경로가 표 19 · 정책 32 · 함수 8로
같은 결과를 냈습니다.

붙인 뒤 확인:

```sql
select count(*) from information_schema.tables
 where table_schema='public' and table_name='sleep_noise_logs';   -- 0
select count(*) from information_schema.columns
 where table_name='sleep_records' and column_name='average_db';   -- 1
select count(*) from information_schema.columns
 where table_name='skin_analyses' and column_name='disease_result'; -- 0
```

> ⚠️ **011은 `sleep_noise_logs`를 지웁니다.** 지금 그 표에 쌓인 지난 밤들의
> 원시 로그는 사라집니다. 집계도 함께 사라지므로(집계 함수가 그 로그를 읽던
> 것이라), **이미 저장된 지난 측정의 평균·최대는 0으로 보입니다.** 새로 재는
> 밤부터 값이 들어갑니다. 논문에 쓸 측정치가 그 표에 있다면 먼저 내려받으세요:
>
> ```sql
> select sleep_record_id, avg(decibel), max(decibel), count(*)
>   from sleep_noise_logs group by 1;
> ```

## 1. 실기기에서 확인해 주실 것

제가 할 수 없는 것들입니다. 시뮬레이터로는 알림·마이크·카메라를 믿을 수
없습니다.

### 시작 전 준비 — 상담·피부를 보시려면 필요합니다

앱은 기본적으로 `10.0.2.2:8000`(안드로이드 에뮬레이터) 또는
`127.0.0.1:8000`을 봅니다. **실기기에서는 둘 다 닿지 않습니다.**

> ⚠️ **터미널이 두 개 필요합니다.** 서버는 켜 둔 채로 계속 돌아야 해서
> 터미널을 잡고 놓지 않습니다. 아래를 한 덩어리로 붙여 넣으면 첫 명령에서
> 멈춘 채 나머지가 실행되지 않습니다.

**터미널 1 — 서버.** 켜 두고 그냥 둡니다.

```bash
cd server
./venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

`Uvicorn running on http://0.0.0.0:8000` 이 뜨고 멈춰 있으면 성공입니다.
끌 때는 `Ctrl+C`.

**터미널 2 — 앱.** 새 창을 엽니다.

```bash
ipconfig getifaddr en0        # PC의 내부 IP. 예: 192.168.0.132
```

나온 주소를 아래에 **직접 적어 넣습니다.** `<PC의 IP>`를 그대로 두면 안 됩니다.

```bash
flutter run --dart-define-from-file=env.json \
            --dart-define=API_BASE_URL=http://192.168.0.132:8000
```

공유기가 IP를 다시 나눠 주면 값이 바뀝니다. 안 닿으면 다시 확인하세요.

**닿는지 먼저 보는 법.** 앱을 켜기 전에 터미널 2에서:

```bash
curl http://192.168.0.132:8000/health
# {"status":"ok","models":{"skin":{"ready":true},"advice":{"ready":true}}}
```

`skin`과 `advice`가 **둘 다 true**여야 합니다. 예전에는 skin이 false인 것이
정상이었는데, 이제 같은 API 키를 쓰므로 둘이 함께 켜집니다.

그다음 **휴대폰 브라우저로 같은 주소**를 열어 보세요. 여기서 안 열리면
앱에서도 안 됩니다. 원인은 대개 셋 중 하나입니다.

- 기기와 PC가 다른 와이파이에 있음 (제일 흔함)
- 공유기가 기기 간 통신을 막음 (게스트 와이파이·AP 격리)
- macOS 방화벽이 python 수신을 막음 (시스템 설정 → 네트워크 → 방화벽)

앱에서 `답변 서버에 연결하지 못했습니다`면 주소 문제,
`로그인이 필요합니다`면 주소는 맞고 인증 쪽입니다.

준비가 번거로우면 상담·피부만 빼고 나머지를 먼저 보셔도 됩니다.

### A. 마이크 −15dB 보정이 검증되지 않았습니다 **[미확인]**

`main.dart`의 `_micOffsetDb = 15.0`은 경험적으로 정한 값입니다. 실제 소음계와
대조한 적이 없어, 앱이 "30dB"이라고 할 때 정말 30dB인지 알 수 없습니다.
**소음 기능 전체가 이 값 위에 서 있습니다.**

휴대폰 소음계 앱만으로는 부족합니다(그것도 보정되지 않았습니다). 학교
실습실 소음계와 맞춰 보시는 게 가장 빠릅니다.

### B. 소음 — 화면이 말하는 '가장 컸던 소리'가 아직 정확하지 않습니다 **[확인함]**

화면은 "측정 중 가장 컸던 소리는 …dB"라고 합니다. `max_db`는 이제 1초 창
최댓값들의 최대라 예전보다 낫지만, **넘어오는 값 자체가 이미 이동평균**입니다
(`main.dart`에서 이전 85% + 새 값 15%). 배경 40dB에서 순간 90dB가 들어와도
45.25dB까지만 올라갑니다.

원본 최댓값을 쓰려면 `main.dart`의 평활 **이전** 값을 함께 넘겨야 합니다.
그러지 않을 거라면 화면 문구를 '가장 높았던 구간'으로 낮추고, 논문에서
LAmax 대응 주장을 빼야 합니다. **아직 어느 쪽도 하지 않았습니다.**

### E. FCM · 소셜 로그인 **[확인함]**

`google-services.json`과 `GoogleService-Info.plist`가 없어 Firebase 초기화가
실패합니다(앱은 계속 뜹니다). `device_tokens`와 예방접종 알림이 여기 걸려
있습니다. **수유 알림은 걸리지 않습니다** — 기기 안에서 도는 로컬 알림입니다.

소셜 로그인은 코드는 준비됐지만 `/auth/v1/settings`에서 Google·Kakao 둘 다
`false`입니다. 애플 로그인은 미구현이고 Apple Developer Program이 필요합니다.

## 3. 배포 전에 반드시

- [ ] **`ANTHROPIC_API_KEY`를 배포 환경 변수로** — 저장소에 넣지 마세요.
      `server/.env`는 gitignore돼 있습니다.

숫자로 말할 수 없습니다.** 대신 아래 셋은 잴 수 있고, 재야 합니다.

1. **같은 사진 3회 반복 시 단계 일치율** — 흔들리면 보호자가 다시 찍을
   때마다 다른 답을 받습니다.
2. **`urgent` 발생률** — 10%를 넘으면 안전선이 아니라 소음입니다.
3. **`unreadable` 비율의 시간대별 분포** — 새벽에 치솟는다면 정확도를 재기
   전에 이미 답이 나온 것입니다.

`caution` 비율이 80%를 넘으면 문구를 더 낮춰야 합니다(§0의 경보 피로).

## 4. 아직 기준이 없어 못 만드는 것

[assessment-rules.md](assessment-rules.md)에 조사 결과가 있습니다.

- **성장·수면·수유·배변 판정** — 임계값을 정한 공인 출처를 찾지 못했습니다.
  2026-08-12에 후보 수치 6건을 다시 조사해 **3건을 기각**했습니다
  (AAP가 말한 적 없는 수치를 제가 잘못 인용한 것 포함).
- 지금 판정이 있는 영역은 **체온·성장·소음** 셋입니다.
- **피부는 판정이 아닙니다.** 규칙 엔진이 아니라 모델이 보고, 단계도
  `caution`/`consult` 둘뿐입니다. 논문에서 다른 판정과 같은 줄에 놓지
  마세요.

없는 기준을 지어내는 것보다 "기록하고 집계만 한다"가 낫다는 것이 지금까지의
결론입니다. 약·병원(⑥)과 예방접종(⑦)이 그 방식으로 만들어져 있습니다.

## 6. 논문 원고 수정

원고(`.docx`)는 저장소에 없어 제가 고칠 수 없습니다. 코드와 어긋나는 곳만
적습니다.

| 절 | 원고 서술 | 실제 |
|---|---|---|
| 시스템 구성 | 판정 규칙을 FastAPI가 수행 | **앱(Dart)의 규칙 엔진**이 계산합니다. 서버는 상담과 피부 사진만 |
| 시스템 구성 | 서버가 범위 검증 | 범위 검증은 앱과 DB의 CHECK 제약이 합니다 |
| DB | 테이블 14개 | **20개** |
| 초록 | "체온·성장·수면·수유" 판정 | 판정이 있는 것은 **체온·성장·소음** |
| 3-2절 ② ④ | "판단한다" | 수유·배변은 **기록하고 집계만** 합니다 |
| 3-2절 ⑦ | 접종 "가능 여부를 판단" | **확인 정보를 제시**합니다. 판정하지 않습니다 |
| 3-3절 | "6개월 초과" | 코드는 **6개월 이상**(`symptomNoteFromMonths = 6`) |
| 피부 | CNN 분류 / 정확도 | **분류기를 쓰지 않습니다.** 비전 LLM이 관찰만 하고 병명을 말하지 않습니다. 정확도를 숫자로 낼 수 없다는 점을 한계로 적어야 합니다 |
| — | 종합 판정 | 없습니다. 영역별 판정만 있습니다 |

**두 가지는 반대로 맞게 됐습니다.**

- "FastAPI가 Supabase Auth 토큰을 검증한다" — 2026-08-12에 `/api/advice`,
  08-13에 `/api/skin/diagnose`에 인증을 넣어 **이제 실제로 검증합니다.**
- "FastAPI가 이미지 추론을 수행한다" — 자체 모델은 아니지만 서버가 사진을
  받아 처리하는 것은 맞습니다. 다만 **"학습한 모델"이라고 쓰셨다면 고쳐야
  합니다.**
