## 1. 실기기에서 확인해 주실 것

제가 할 수 없는 것들입니다. 시뮬레이터로는 알림·마이크·카메라를 믿을 수
없습니다.

### 시작 전 준비 — 상담(챗봇)을 보시려면 필요합니다

앱은 기본적으로 `10.0.2.2:8000`(안드로이드 에뮬레이터) 또는
`127.0.0.1:8000`을 봅니다. **실기기에서는 둘 다 닿지 않습니다.**

> ⚠️ **터미널이 두 개 필요합니다.** 서버는 켜 둔 채로 계속 돌아야 해서
> 터미널을 잡고 놓지 않습니다. 아래를 한 덩어리로 붙여 넣으면 첫 명령에서
> 멈춘 채 나머지가 실행되지 않습니다.

**터미널 1 — 서버.** 켜 두고 그냥 둡니다.

```bash
cd server
./venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

`Uvicorn running on http://0.0.0.0:8000` 이 뜨고 멈춰 있으면 성공입니다.
끌 때는 `Ctrl+C`.

`피부 모델이 설정되지 않았습니다` 경고는 정상입니다 — 그 기능만 503이고
나머지는 그대로 돕니다.

**터미널 2 — 앱.** 새 창을 엽니다.

```bash
ipconfig getifaddr en0        # PC의 내부 IP. 예: 192.168.0.132
```

나온 주소를 아래에 **직접 적어 넣습니다.** `<PC의 IP>`를 그대로 두면 안 됩니다.

```bash
flutter run --dart-define-from-file=env.json \
            --dart-define=API_BASE_URL=http://192.168.0.132:8000
```

공유기가 IP를 다시 나눠 주면 값이 바뀝니다. 안 닿으면 다시 확인하세요.

**닿는지 먼저 보는 법.** 앱을 켜기 전에 터미널 2에서:

```bash
curl http://192.168.0.132:8000/health
# {"status":"ok","models":{"skin":{"ready":false},"advice":{"ready":true}}}
```

그다음 **휴대폰 브라우저로 같은 주소**를 열어 보세요. 여기서 안 열리면
앱에서도 안 됩니다. 원인은 대개 셋 중 하나입니다.

- 기기와 PC가 다른 와이파이에 있음 (제일 흔함)
- 공유기가 기기 간 통신을 막음 (게스트 와이파이·AP 격리)
- macOS 방화벽이 python 수신을 막음 (시스템 설정 → 네트워크 → 방화벽)

앱에서 상담을 열었을 때 `답변 서버에 연결하지 못했습니다`면 주소 문제,
`로그인이 필요합니다`면 주소는 맞고 인증 쪽입니다.

준비가 번거로우면 상담만 빼고 나머지를 먼저 보셔도 됩니다.

### A. 체온을 저장하다 실패하면 기록이 중복될 수 있습니다 **[확인함]**

`TemperatureRecordService.save()`가 두 번에 나눠 넣습니다.

```
1) temperature_records  insert ... select().single()
2) temperature_symptoms insert (증상이 있을 때만)
```

2단계가 실패하면 1단계는 이미 저장돼 있는데 화면은 "저장하지 못했습니다"를
띄웁니다. 다시 누르면 같은 체온이 한 번 더 들어갑니다.

**008 적용 전까지는 함께 키우는 보호자에게 이것이 상시 발생합니다** — 증상
저장이 RLS에 매번 막히기 때문입니다.

고치는 방법 둘: 2단계 실패를 치명적으로 보지 않고 "체온은 저장됐고 증상은
저장하지 못했습니다"로 알리거나, Postgres 함수 하나로 묶어 한 트랜잭션에
넣거나.

온보딩(`child_info_page`)도 같은 패턴입니다 — `create` 뒤 `saveRecord`가
실패해도 롤백이 없고 재시도하면 **아이가 2행** 생깁니다. 중복 행을 지울
수단은 앱에 없습니다.

### B. 조회 실패를 "기록 없음"으로 보여줍니다 **[확인함]**

원칙 2를 어기는 곳이 다섯입니다. 예방접종은 고쳤습니다(`756ea81`).

| 화면 | 지금 | 결과 |
|---|---|---|
| 홈 | `catch { debugPrint }` → 타일에 '기록 없음' | 기록이 정말 없을 때와 글자가 같음 |
| 홈 (수유 알림) | 실패하면 `lastFedAt`이 null → **예약된 알림이 취소됨** | 통신 없이 앱을 한 번 열면 그날 알림 1회를 놓침 |
| 마이페이지 | 같은 패턴 | |
| 함께 키우기 | 아이 조회 실패를 "아직 등록된 아이가 없어요"로 단정 | 아이가 있는데 초대 코드 만들 경로가 사라짐 |
| 상담 맥락 | 실패 시 판정까지 버리고 "아이 정보를 등록하면"이라 안내 | 등록한 사용자에게 등록하라고 말함 |

다섯을 한 번에 고치는 편이 낫습니다. 화면마다 로딩/실패/값 **3-상태**로
바꾸는 같은 작업입니다.

### C. 조회 창이 기본 limit보다 먼저 잘립니다 **[확인함]**

"최근 N일"을 말하면서 실제로는 최신 20건만 봅니다.

- **약·병원 반복 카드** — 제목은 "지난 90일"인데 최신 20건만 셉니다.
  3주 전 구토 3건이 통째로 사라집니다.
- **접종 전 확인 3일** — 체온 최신 20건만 봅니다. **열이 나서 자주 잰
  아이일수록** 3일 창 앞쪽(첫날 고열)이 빠집니다. 앱 자체가 2시간 간격
  재측정을 권하므로 흔한 상황입니다.

서비스에 `since` 파라미터를 넣어 `.gte(...)`로 창 전체를 받는 것이 답입니다.
이력 목록은 상위 20건 그대로 두면 됩니다.

### D. 소음 — 저장하는 dB가 '가장 컸던 소리'가 아닙니다 **[확인함]**

화면은 "측정 중 가장 컸던 소리는 …dB"라고 하는데, 저장되는 값은 이동평균
(이전 85% + 새 값 15%)입니다. 배경 40dB에서 순간 90dB가 들어와도 45.25dB로
기록됩니다. `NoiseReading.maxDecibel`은 어디서도 읽지 않습니다.

`sleep_noise_logs`에 `peak_db`를 추가해 원본 최대를 함께 저장하거나, 문구를
'가장 높았던 평균 구간'으로 고치고 LAmax에 대응한다는 주장을 문서에서
빼야 합니다.

### E. 소음 — 중지 후 고정 2초만 기다립니다 **[확인함]**

`_showResult`가 `Future.delayed(2초)` 뒤 조회합니다. 백그라운드의 `finish()`는
왕복이 세 번이라 느린 망에서는 그 안에 안 끝납니다. 그러면 표본 부족으로
안내되거나 마지막 배치가 빠져 평균이 왜곡됩니다.

`noise_session_ended`를 `Completer`로 받아 `Future.any([완료, 15초])`로
기다리고, 시간이 넘으면 사실대로 알리는 것이 맞습니다.

### F. 마이크 −15dB 보정이 검증되지 않았습니다 **[미확인]**

`main.dart`의 `_micOffsetDb = 15.0`은 경험적으로 정한 값입니다. 실제 소음계와
대조한 적이 없어, 앱이 "30dB"이라고 할 때 정말 30dB인지 알 수 없습니다.
**소음 기능 전체가 이 값 위에 서 있습니다.**

휴대폰 소음계 앱만으로는 부족합니다(그것도 보정되지 않았습니다). 학교
실습실 소음계와 맞춰 보시는 게 가장 빠릅니다.

### G. 성장 화면 — 24개월 초과와 입력 범위 **[확인함]**

- 30개월 아이의 점이 `clamp(0,24)` 때문에 **24개월 눈금 위에** 찍힙니다.
  기록이 여러 건이면 같은 x에 겹쳐 수직선이 됩니다. 판정은 이유 없이 안 뜹니다
  (LMS 표가 0~24개월이라 `assess`가 null).
- 몸무게에 "3200"을 넣으면 `numeric field overflow` 영문 예외가 그대로
  스낵바에 뜹니다. 온보딩은 같은 값에 한국어로 안내합니다.

### H. 예방접종 — 당일에 '오늘'과 '지남'이 동시에 **[확인함]**

`isOverdue`가 `scheduledOn.isBefore(now)`인데 `scheduledOn`은 자정,
`now`는 현재 시각입니다. 같은 화면의 D-day 계산은 날짜만 비교해서, 접종일
당일에 '오늘'과 빨간 '지남'이 함께 뜹니다.

### I. 피부 화면이 없는 기능을 약속합니다 **[확인함]**

"AI가 피부 상태를 알려드립니다"라고 적혀 있지만 누르면
`서버 연동 실패: DioException … 503` 영문 원문이 뜹니다. 서버가 내려준 한국어
안내는 쓰이지 않습니다. 사진 선택이 실패해도 아무 반응이 없습니다.

그리고 모델이 붙는 순간 **"진단 결과: 흑색종 (88.4%)"**를 그대로 출력하도록
돼 있습니다. 이 앱은 의료기기가 아니고 진단명을 말하지 않기로 했습니다.

### J. FCM · 소셜 로그인 **[확인함]**

`google-services.json`과 `GoogleService-Info.plist`가 없어 Firebase 초기화가
실패합니다(앱은 계속 뜹니다). `device_tokens`와 예방접종 알림이 여기 걸려
있습니다. **수유 알림은 걸리지 않습니다** — 기기 안에서 도는 로컬 알림입니다.

소셜 로그인은 코드는 준비됐지만 `/auth/v1/settings`에서 Google·Kakao 둘 다
`false`입니다. 애플 로그인은 미구현이고 Apple Developer Program이 필요합니다.

## 6. 논문 원고 수정

원고(`.docx`)는 저장소에 없어 제가 고칠 수 없습니다. 코드와 어긋나는 곳만
적습니다.

| 절 | 원고 서술 | 실제 |
|---|---|---|
| 시스템 구성 | 판정 규칙을 FastAPI가 수행 | **앱(Dart)의 규칙 엔진**이 계산합니다. 서버는 추론과 상담만 |
